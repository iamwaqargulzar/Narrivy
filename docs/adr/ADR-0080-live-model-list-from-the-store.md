# ADR-0080: The model list comes from the Store repository

Status: Accepted (2026-11-04).

## Context

- The owner: "implement live feed: it will check Hugging Face for the model
  list; the list isn't hard coded."
- Until now the catalog (speech models, OpenVINO packs, language models,
  runtimes) was compiled in (`crates/narrivy-model-manager/seed/*.json`), so
  every new model needed a release.
- Every download is already verified against pins in the catalog: a
  40-character revision, a file SHA-256 or a pack manifest's SHA-256 and
  size (ADR-0078, ADR-0079).

## Decision

- The Store repository publishes the same four files under `catalog/` on
  its `main` branch (`narrivy/store`). They are generated by
  `scripts/build_store_catalog.py` from the built-in copies plus
  `packaging/store/catalog-additions.json`, pinned to the Store commit that
  holds the new files.
- The service (`catalog_feed.rs`) fetches them with the same `curl` helper,
  host and redirect rules as model downloads, at most 1 MB each, only when a
  model list is asked for (`ListModels`, `ListStore`, `ListLanguageModels`)
  and the copy in use is over an hour old (five minutes after a failure).
  Nothing is fetched while nobody opens Models or the Store.
- A file is used only after it passes the checks the built-in one passes
  (`check_live`: version 1, the registry's own validation, at most 256
  entries). The last good copy is kept in `<state>/catalog/` (0600) and used
  at the next start; otherwise the built-in list is.
- A live entry replaces the built-in one with the same id; built-in entries
  the live copy leaves out stay listed, so an installed model never drops
  out.
- Status reports `catalog.live=built_in|cached|fresh[:failed:<code>]`.

## Consequences

- New models are published without a Narrivy release.
- The list itself is trusted as far as the `narrivy` organisation on
  Hugging Face and TLS are: whoever can write to `narrivy/store` can add an
  entry. They cannot change the bytes of an entry already pinned in this
  build, and a download is always checked against its entry's pins. A
  signed catalog (a key compiled into the service) is the next step if
  more than the owner can write to the organisation.
- One small request per hour at most while the user looks at a model list
  is the only network use besides downloads the user starts.
