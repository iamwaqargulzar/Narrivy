# Agent Work Order — P1 Core, IPC, Persistence & Privacy Baseline

## Mission
P1 decides and implements session state machine, cancellation/timeouts, typed outcomes, daemon/client protocol, same-user IPC, crash journal, privacy-policy baseline, persistent store/migrations, daemon lifecycle, and deterministic mock path.

## Required requirement IDs
`FUN-005`, `FUN-020`, `OPS-006`, `PORT-002`, `PORT-003`, `PORT-004`, `PORT-005`, `REL-001`, `REL-007`, `SEC-005`, `TEST-003`

## Execution
1. Read `docs/maintainers/phases/phase-01-core-ipc.md`, ADRs `ADR-0012-daemon-lifecycle.md` and `ADR-0013-persistence.md` (create them first), `BUILD_TARGET.json`, and `agent/PHASES.json`.
2. Run `python3 scripts/doctor.py --json` and baseline tests for touched layers.
3. Implement session state machine, cancellation/timeouts, typed outcomes, daemon/client protocol (versioned), same-user IPC, recovery journal, privacy-policy baseline, and persistence/migrations per ADRs.
4. Add deterministic contract tests for state machine, IPC handshake/peer validation, migration interruption/recovery, and privacy enforcement.
5. Provide a mock vertical slice (daemon/core/null platform) for contract E2E without claiming hardware support.
6. Mark requirements passed only with schema-valid evidence; run `python3 scripts/phase_gate.py --phase P1` until it passes, then advance.

## Autonomy/failure rule
Build errors, test failures and API drift are work items. Follow `agent/FAILURE-RECOVERY.md`; do not ask the owner for a technical choice the repository, host, upstream documentation or a safe experiment can resolve.

## Non-regression
Do not claim real hardware/platform support from mocks.

## Done means
The phase specification's exit evidence exists, all primary release requirements for P1 are passed with schema-valid evidence bound to commit/build, the gate exits 0, and the phase report validates its schema and captures commands/results/measurements/deviations/known non-blockers.

## Module contract requirement

Introduce an internal `ModuleRegistry`/capability registry and typed module identity/health/version descriptors so activation, capture, audio processing, ASR/compute, context and delivery implementations can be replaced without domain coupling. Keep the contracts internal-evolving; do not publish a Rust dylib ABI.
