# Agent Work Order — P10 Packaging & Reproducible Release Engineering

## Mission
P10 produces the `.deb` (single Linux 1.0 installation artifact — owner decision 2026-08-22, no AppImage/portable package) with immutable builder baselines, dependency inventory, SBOM, notices, checksums, build identity, and provenance.

## Required requirement IDs
`OPS-002`, `OPS-003`, `OPS-004`, `OPS-005`

## Execution
1. Read `docs/maintainers/phases/phase-10-packaging.md`, `docs/maintainers/operations/reproducible-builder.md`, and `docs/maintainers/operations/update-policy.md`.
2. Produce the .deb from the immutable builder baseline (digest recorded), with desktop metadata, daemon ownership, XDG paths, and upgrade/migration handling. Do NOT build an AppImage for 1.0 (follow-on only, requires ADR to re-promote).
3. Generate checksums, SBOM, dependency/license inventory, provenance, and build identity; verify clean-VM install/upgrade/uninstall and real dictation from package.
4. Emit evidence and pass gate; retain unsigned artifacts if signing credentials absent (blocker recorded, not faked).

## Autonomy/failure rule
Build errors, test failures and API drift are work items. Follow `agent/FAILURE-RECOVERY.md`; do not ask the owner for a technical choice the repository, host, upstream documentation or a safe experiment can resolve.

## Non-regression
Do not claim real hardware/platform support from mocks.

## Done means
The phase specification's exit evidence exists, all primary release requirements for P10 are passed with schema-valid evidence bound to commit/build, the gate exits 0, and the phase report validates its schema and captures commands/results/measurements/deviations/known non-blockers.
