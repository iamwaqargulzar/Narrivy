# Agent Work Order — P4 Audio Reliability

## Mission
P4 hardens capture, microphone lifecycle, PipeWire behavior, failure recovery, and only the proven 1.0 audio policies (leave + at least one crash-safe duck or pause).

## Required requirement IDs
`FUN-002`, `FUN-006`, `FUN-007`, `FUN-011`, `FUN-012`, `PERF-006`, `REL-004`, `REL-005`, `REL-009`

## Execution
1. Read `docs/maintainers/phases/phase-04-audio-pipewire.md` and P0F audio findings.
2. Implement bounded pre-roll, format conversion off real-time thread, deterministic mic ranking/override/hotplug, and `leave` + at least one crash-safe `duck`/`pause` with restoration journal/watchdog.
3. Add harnesses for stream churn, suspend/resume, forced-kill, hotplug, and new-stream-during-session inheritance.
4. Verify no inference on audio thread, no log leakage, and restoration after abrupt death where platform allows.
5. Emit evidence and run `python3 scripts/phase_gate.py --phase P4` until it passes.

## Autonomy/failure rule
Build errors, test failures and API drift are work items. Follow `agent/FAILURE-RECOVERY.md`; do not ask the owner for a technical choice the repository, host, upstream documentation or a safe experiment can resolve.

## Non-regression
Do not claim real hardware/platform support from mocks.

## Done means
The phase specification's exit evidence exists, all primary release requirements for P4 are passed with schema-valid evidence bound to commit/build, the gate exits 0, and the phase report validates its schema and captures commands/results/measurements/deviations/known non-blockers.

## Modular audio requirement

Capture, VAD, resampling/preprocessing and noise suppression are separate replaceable internal contracts. Ship a conservative built-in chain first; third-party external loading is not required for 1.0. A processor failure must bypass/degrade safely without crashing the capture owner or losing the session.
