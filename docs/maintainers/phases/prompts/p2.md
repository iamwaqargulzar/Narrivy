# Agent Work Order — P2 Walking Skeleton

## Mission
P2 delivers the first real plain but working path: trigger → microphone → real local ASR → final text → external target or Inbox fallback on both desktop lanes with cancellation, redacted logs, recoverable text, and CPU correctness.

## Required requirement IDs
`FUN-001`, `FUN-004`, `FUN-009`, `FUN-010`, `FUN-013`, `REL-002`, `REL-003`, `TEST-004`

## Execution
1. Read `docs/maintainers/phases/phase-02-walking-skeleton.md` (walking skeleton), P0F capability matrix, and `agent/PHASES.json`.
2. Run `python3 scripts/doctor.py --json` and baseline tests.
3. Wire real platform adapters (trigger via portal, PipeWire capture, text delivery router) and real local ASR (CPU correctness path) into the daemon; keep UI minimal/plain.
4. Implement bounded fallback (semantic → clipboard → portal → Inbox) with target-aware spacing/punctuation, cancellation without stale output, recoverable final text, bounded fallback, and redacted logs.
5. Exercise on both desktop lanes (native where possible) across target matrix (native Wayland, browser, Electron, terminal, XWayland) with Unicode/multiline fixtures.
6. Emit schema-valid evidence bound to commit/build/env; run `python3 scripts/phase_gate.py --phase P2` until it passes; preserve working app for later phases.

## Autonomy/failure rule
Build errors, test failures and API drift are work items. Follow `agent/FAILURE-RECOVERY.md`; do not ask the owner for a technical choice the repository, host, upstream documentation or a safe experiment can resolve.

## Non-regression
Do not claim real hardware/platform support from mocks.

## Done means
The phase specification's exit evidence exists, all primary release requirements for P2 are passed with schema-valid evidence bound to commit/build, the gate exits 0, and the phase report validates its schema and captures commands/results/measurements/deviations/known non-blockers.
