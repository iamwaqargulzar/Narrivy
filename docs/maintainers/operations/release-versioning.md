# Release and Versioning Policy

Before 1.0, use semantic versioning with explicit pre-release channels: alpha, beta, rc, stable.

A release candidate requires:
- migration coverage;
- supported-platform compatibility matrix;
- security/privacy review for changed data flows;
- performance regression report;
- accessibility smoke tests;
- model/catalog compatibility review;
- signed/checksummed artifacts;
- known issues and rollback path.

Application, model catalog and plugin ecosystem versions are independent.
