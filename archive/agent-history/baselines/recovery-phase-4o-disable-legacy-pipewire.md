# Recovery Phase 4O — disable legacy non-strict PipeWire capture

Status: controlled non-release implementation independently reviewed PASS.
Release remains blocked.

## Objective

Remove the daemon-local temporary-WAV microphone path without pretending that
a partial call-site substitution provides a truthful non-strict live pipeline.

## Implemented scope

- deleted the service-local `capture_pipewire` helper and its public re-exports;
- made non-strict PipeWire an invalid static composition;
- rejected invalid programmatic selection before journal/session/worker
  admission;
- disabled advertised non-strict pipelines for the defensive invalid state;
- retained a no-side-effect terminal worker guard for future internal bypass;
- added source, configuration, and pre-admission regression tests; and
- recorded the boundary in ADR-0047.

## Controlled verification

- fixture-module source guard proves the removed helper, native `capture.wav`,
  and ordinary temp-directory writer tokens do not return;
- configuration tests reject non-strict PipeWire while accepting both strict
  owned-capture compositions;
- handler tests prove StartSession and SelectPipeline reject with zero journal
  records, session slots, workers, or delivered sink values; and
- Stop/Cancel subsequently report no active session.

## Preserved behavior

- the default sine/mock lane and explicit WAV fixture lane;
- strict `linux-mic-inbox` and `linux-mic-wtype-inbox` composition;
- owned fileless `PipeWireCapture` batch and streaming adapters and their
  deterministic child-reaping tests.

## Explicit residual risk

Non-strict microphone behavior is disabled, not qualified. A future migration
must defer `Listening` until source readiness and compose the portable owned
capture lifecycle end to end. Helper executable identity/TOCTOU, descendant
containment, memory forensic hardening, resolved device identity, native
qualification, supply-chain advisories, evidence, and packaging remain blocked.

## Guardrails

No microphone/native run, evidence/index or requirement change, manifest
reseal, packaging, protected-file edit, commit, push, or release claim is
permitted.
