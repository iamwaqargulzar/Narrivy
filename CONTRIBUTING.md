# Contributing

Narrivy uses specification-led development.

## Pull requests
- One coherent capability or refactor per PR.
- Link requirement IDs and ADRs.
- Include tests and documentation.
- State privacy/security impact.
- State performance impact for hot paths.
- No unrelated formatting churn.
- No copied code from competitive/reference projects.

## Commit style

Use Conventional Commits where useful: `feat:`, `fix:`, `refactor:`, `perf:`, `test:`, `docs:`, `build:`, `ci:`, `chore:`.

## Review priorities
1. correctness and data safety;
2. architecture boundaries;
3. privacy/security;
4. reliability/recovery;
5. UX/accessibility;
6. performance;
7. maintainability.
